# ptoart：分析与重构说明

## 最重要的结论

上游项目的价值在已训练的人像风格模型，而主要维护障碍在模型周围的工程代码。上游同时使用 PyTorch 生成器、face-alignment 检测关键点和 TensorFlow 冻结图分割；直接替换网络、裁剪比例或归一化会影响官方权重效果。因此本次选择先稳定外层，再扩展功能，没有声称改进模型画质。

基线代码来自 [minivision-ai/photo2cartoon](https://github.com/minivision-ai/photo2cartoon)，提交 `6204e27a71620500c2f5b2ffd36646b0e2e5c110`。许可证为 MIT，保留原版权声明。

## 原有流程与薄弱点

照片先检测最大人脸与 68 点关键点，旋转对齐并按固定比例扩框裁剪，再使用 TensorFlow 模型提取前景掩码。白色背景的 256×256 RGB 头像归一化为 `[-1,1]`，输入带 hourglass 和 Soft-AdaLIN 的生成器，输出再与掩码合成。

原 Torch、ONNX 与 Cog 脚本复制了这套流程，容易产生修复不一致。顶层解析命令导致模块不可安全导入；相对路径与空目录名易出错。模型没有显式切换 eval 模式，输出转 uint8 前没有裁剪。坏图和无脸缺少统一错误语义，保存返回值没有检查。Cog 每次请求重建预处理与网络，TensorFlow 会话缺少释放方法。旧依赖与当前 Python 不兼容，缺少安装元数据和自动化测试。

## 新结构

```text
ptoart/
  config.py       参数校验、模型目录与路径解析
  io.py           RGB 图像读写、EXIF、像素限制、原子防覆盖写入
  backends.py     Torch/ONNX 装载和统一 run(NCHW) 接口
  pipeline.py     预处理 -> 归一化 -> 推理 -> 后处理
  errors.py       无脸、输入输出、模型异常分类
  cli.py          convert / batch / doctor
models/           保留上游网络和训练实现
utils/            兼容预处理、惰性导出及会话生命周期
```

`ArtPipeline` 是唯一的新推理流程。后端输出必须是有限数值的 `[1,3,256,256]`，新后端可实现 `run()` / 可选 `close()` 后注入，不需要复制图像处理。预处理也可注入，便于隔离测试；这不是对未测试的新检测器自动兼容的承诺。

推理使用 `eval()` 和 `inference_mode()`；模型实例由调用者顺序复用。新 Torch 后端采用受限权重加载、严格 state_dict 校验；ONNX 使用元数据解析张量名并按用户设备要求选择 provider。所有框架都延迟到真正使用时导入。

## 已完成的功能扩展

新增目录批处理，支持递归、逐图失败隔离和 JSON 汇总；同名不同扩展保留区分，不吞掉失败，不默认覆盖。新增透明输出与自定义背景，以及模型输出/原始人脸的像素混合。支持 Unicode 路径、EXIF 旋转、灰度和透明输入，设置解码前像素限制，明确 RGB/BGR 边界。增加 CLI 环境诊断及 Python API。

这些功能不引入新的云服务，不上传人像。安装依赖和 face-alignment 首次获取资产时仍可能联网；部署方应独立审计第三方行为。

## 为稳定性而保留的部分

生成器参数名、模块层级、256 输入、白底归一化、原裁剪比例及最大脸策略未重写。官方权重文件名保持不变。训练循环、损失函数与默认数据集名保持兼容；项目名、安装名和新命令为 `ptoart`。

默认白底、完整强度的数学流程与原项目相同，但浮点精度、显式 eval、输出范围裁剪、框架版本和检测库版本可能使结果不逐像素相同。本次不伪称已用官方权重完成误差基准。

旧 Python 推理入口仍返回 BGR，新 API 返回 RGB/RGBA。旧命令新增安全行为：拒绝覆盖已存在目标、缺参明确报错。上游 `Photo2Cartoon` 的非公开内部属性不承诺逐项兼容。

## 尚未解决的限制

模型权重和检测器资产未打包，完整真实效果待验收。上游分割模型专为裁剪人脸训练，不适合整幅半身照。数据人群覆盖有限；调整工程代码不会修复模型偏差。

训练实现仍是遗留组件：CUDA 训练路径、旧 SciPy `misc.imsave` 辅助函数和历史 checkpoint 加载尚未全面现代化。此版本不承诺训练可直接在所有现代依赖组合中运行。Cog 配置更新为候选组合，容器、真实 HTTP 服务和并发未验证。

没有新增未经验证的多风格、视频、超分辨率、多人合照回贴、公开 Web API 或前端。这些会引入额外模型、队列、身份数据保护和部署风险，不应混入“保持稳定”的第一轮重构。

## 接手后的验收重点

先取得可信官方权重并记录哈希，固定一套完整依赖和检测器资产，完成原版与新版、Torch 与 ONNX 的同输入输出比对；再验证 CPU/GPU 连续批次的时间、内存和资源释放。准备不同年龄、肤色、性别、遮挡和无脸样本，区分检测失败与风格模型局限。真实权重未验收前，保留此版本的预览标记。
